# v0.1.7

Verifier fixes from an internal review and one external report. The verifier now holds each
reveal to its own paid act, each match to one paid join and each Fight Hour window to a
commitment published in time, and it reports entries that move no value apart from replayed
ones. Public source for audit, under BUSL-1.1.

## Deployed program

The on-chain program is unchanged from v0.1.4: same program id, same source and the same
verifiable build hashes listed in [v0.1.4](https://github.com/Crypto-of-Thrones/core/blob/v0.1.4/docs/releases/v0.1.4.md). No file under `programs/` changed.

## Changes

### Verifier: external report

- **Fight Hour commitment checked.** A hunt hour that overlaps a Fight Hour window is replayed in
  full only against the realm log commitment of that day. The payout check needs that commitment
  to be published before the drand round the window is drawn from. A commitment of another day,
  one published after the round, or one that does not match the window used fails the rule. When
  the commitment record cannot be read, the entry is `SIG` with `why: fight record not read` (or
  `fight record not available` in the Statement), never `PASS`.

  Reported by byfor. Thank you.

### Verifier: internal review

- **Act and reveal pairing.** Each reveal is held to exactly one paid act of its own kind, and a
  reveal credits only what its payout rule gives. A login or first claim credits only its coin
  items, and the credit of a signature-only reveal is still checked.
- **One join per match.** A Duel or Joust bind needs the paid queue join of its lord, and one
  join backs one bind only.
- **Current entry format.** Every action entry must use the current (v2) format once the chain of
  the account uses it, and always on mainnet. An older action entry fails wherever it is.
- **Field Luck rule bound to the round time.** The live Field Luck rule of a raid is chosen from
  the era of its drand round, not from the time of the entry alone.
- **Masked reveal.** An act whose reveal is served masked by the public view ends as `hidden`,
  never `PASS`. A masked list of account ids in a reveal gives `hidden` as well.
- **Masked order signature.** An on-chain order whose signature is served masked by the public
  view reads `hidden`, not `bad`.
- **PvP defense after a cancel.** When a raid hold is released (`pvpDefense` cancel) and held
  again, its reveal binds to the live act, not the cancelled one.
- **No value moved.** An entry with no rule to re-run passes only when its kind is on a fixed
  list of kinds that move no value (`INERT_KINDS` in `web/js/ledgerverify.js`) and it holds only
  the fields its kind is written with and no balance change. Its row says `rule=none` and
  `(no value moved)`, and the summary counts these entries on a `NOTE:` line. Any other entry with
  no rule to re-run is `SIG` with `why: no rule` and the run ends `PASS, NOT FINAL` with the
  `norule` reason. An entry that carries a draw is never reported as `no rule`, so it always
  counts in the `replayed X of N draw entries` line.
- **Grants re-checked.** Credits are held to the rule of their kind again: fixed reward tables,
  forced Hero Box upgrades with their pity counter on record, raid and hold acts with their
  inputs, a lake trip with its catch size, a Duel log with the game's time limit, an on-chain
  order with a well-formed Solana signature, and the balance stamp era by time and chain order.
  An unanchored hour dated in the future fails.

### Withdrawals

- privacy: on-chain withdrawal references no longer link a wallet to a game account; earlier withdrawals keep the previous form

See [What a run proves](../../README.md#what-a-run-proves) in the README for what `PASS`, `SIG` and
`(no value moved)` mean.

## Verify this release

```sh
git clone https://github.com/Crypto-of-Thrones/core.git && cd core
git checkout v0.1.7
node tools/replay-hunt-test.mjs
node tools/verify/verify.mjs <audit-id> --mainnet --base https://api.cot.gg \
  --rpc https://api.mainnet-beta.solana.com --program Cyz7fwhJomMxGtNtj752YcuoSvKASRaYTzrxhHu31FaC
```

Read the `replayed X of N draw entries` line before the verdict. `core-manifest.json` holds the
SHA-256 of every file, the `tree` hash of the whole release and the `rules` commit.
