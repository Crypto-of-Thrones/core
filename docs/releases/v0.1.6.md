# v0.1.6

Verifier fixes from external reports and a code review, the Squire price rule of the live game,
and a clearer verifier summary. Public source for audit, under BUSL-1.1.

## Deployed program

The on-chain program is unchanged from v0.1.4: same program id, same source and the same
verifiable build hashes listed in [v0.1.4](v0.1.4.md). No file under `programs/` changed.

## Changes

### Verifier: external reports 4, 5 and 6

These three issues were reported by an independent security researcher. Thank you.

- **Hunt reveal needs the engine reference (report 4).** A hunt or away reveal whose draw round is
  on or after 2026-11-14 00:00 UTC (`HUNT_ENGINE_FROM`) must publish `refs.engine`. Without it the
  rule replay fails. Reveals before that date keep the previous rule.
- **Summon act count matches the reveal (report 5).** The summon rule now requires the paid act's
  `n` to be a safe integer equal to the reveal's `n`, so a reveal can no longer claim more (or
  fewer) summons than were paid for.
- **Joust win cap (report 6).** The win of a Joust is capped by the current entry fee minus the pool
  share (`joustWinCap`). The older fixed cap applies only to entries charged under the balance
  versions that predate the price change, or, for unstamped entries, to draws before
  2026-11-13 00:00 UTC (`BALANCE_STAMP_FROM`). A Joust act with no `win` is accepted only for
  draws before 2026-11-15 00:00 UTC (`JOUST_WIN_FROM`). A queue match reads its charge from the
  queue join act (`joustCharge`).
- **Partial history waits instead of passing.** Summon and Joust reveals are now marked as needing
  their paid act. When the act (or, for a queue match, the join act) is not in the downloaded
  entries and the run does not start at seq 1, the entry is reported as `wait` (`why: act`) rather
  than replayed without it.

### Verifier: review fixes

- **No silent pass without a replay (R1).** Each server deploy stamps its own commit on the
  entries it writes, so a run with a release that matches none of them used to skip every rule
  replay and still print `PASS` with exit code 0. A passing run that has draw entries and replayed
  none of them now prints a `NOT VERIFIED: 0 of N draw entries replayed` line (`noReplay` in
  `--json`), names the release to run or `--rules-ref any`, and exits with code 3. Accounts with no
  draw, or with at least one replayed draw, keep exit code 0.
- **Replay summary on every run (R1 follow-up).** Every run prints
  `replayed X of N draw entries (Y signature only, Z other rules)` before its verdict, and `--json`
  carries the same counts in `replay` (`replayed`, `total`, `signatureOnly`, `otherRules`). N
  counts ledger entries that carry a draw, so a paid act and its reveal are two entries. Exit code
  0 only says that every check that ran passed; read this line to see how many outcomes were
  recomputed.
- **Merkle step documented (R1 follow-up).** The Merkle proof step runs only with `--acct` (the
  account's own 40 hex id, which the public proof leaves out) and is reported as `skip` otherwise.
  The README now says so.
- **Export path normalization (R2).** The export tool normalizes every allowlist path before its
  deny and exclude checks and refuses absolute, empty or `..` paths, so a path written as
  `./file` can no longer bypass them. The exported files are unchanged by this fix.
- **Account argument (R6).** The README examples now take the account's public audit id (32
  characters of `a-z` and `2-7`, as in the game's public audit links) instead of a 40 hex account
  id, which the verifier refuses. The flag table lists `--acct` for the Merkle step.

### Rules

- `web/js/ledgerverify.js`: the Squire act carries a US$ reference (`refs.usd`). The verifier checks
  it against the published daily price record (`<base>/realm/index/day/<day>`): the record hash, the
  average price, its age (at most 2 days, `SQUIRE_USD_MAX_DAYS`) and that no newer clean record was
  already in force. A mismatch fails as `usdRef`; an unreadable record is `wait`. The Squire price
  is then recomputed from that reference, with the page promotion price when the act names one.
- `web/js/squire.js`: Squire full price from the US$ reference (`squireFullPrice`) and the age rule
  of the reference (`usdRefAge`, `usdRefFresh`).
- `web/js/data.js`: Squire US$ price.
- `web/js/realmlive.js`: reads the US$ reference of the realm index (`usdRefOf`).
- `web/js/pagepromo.js`: new in the public tree, the promotion price imported by the verifier.

### Repository

- New root `package.json` with `{ "type": "module" }`: every `.js` file loads as an ES module on any
  supported Node.js version. Requirements are now Node.js 20.19+ or 22+ (previously "20 or
  later"). There are still no dependencies to install.
- The export tool denies the anti-cheat tools, so no allowlist entry or exported import can ship
  them (R3). The exported files are unchanged by this fix.
