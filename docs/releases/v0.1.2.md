# v0.1.2

Verifier fixes found in a full review of the ledger checks. The ledger format, the draw
derivation and the on-chain program are unchanged.

## Changes

- **Proofs bound to the account.** An epoch proof whose leaf was recorded under another account
  used to pass. The verifier now refuses it with `acct`, both in `tools/verify/verify.mjs` and in
  the in-game statement check (`web/js/ledgerverify.js`).
- **Drawn reveals need their draw.** A reveal of a drawn kind that carries no `draw` field used to
  skip the rule replay and pass. It now fails with `draw`. The server records the draw on every
  such reveal, so genuine entries are unaffected.
- **Active accounts.** The newest entries of an active account could land while the verifier was
  downloading the days and were read as a cut in the chain. They are now read as what they are.
- **Hunt replay.** When a mercenary leaves and another takes the same post in the same roster
  change, the duel area now follows the new unit, so a hunt resumed from a snapshot matches the
  live one.

## Verify this release

```sh
git clone https://github.com/Crypto-of-Thrones/core.git && cd core
git checkout v0.1.2
node tools/replay-hunt-test.mjs
node tools/verify/verify.mjs <account> --base https://api-beta.cot.gg --rpc https://api.devnet.solana.com
```

`core-manifest.json` holds the SHA-256 of every file, the `tree` hash of the whole release and
the `rules` commit.
