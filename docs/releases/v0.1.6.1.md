# v0.1.6.1

Verifier hotfix: honest ledger entries that the v0.1.6 verifier reported as failures now verify
again, and the verifier names the reason when a run stops on a masked row. Public source for
audit, under BUSL-1.1.

## Deployed program

The on-chain program is unchanged from v0.1.4: same program id, same source and the same
verifiable build hashes listed in [v0.1.4](v0.1.4.md). No file under `programs/` changed.

## Changes

### Verifier: masked lists of account ids

- **A masked list shows its mask.** The public day route replaces every account id with
  `hidden`, also inside lists (for example `refs.rows` and `refs.pool` of a `pvpReroll` reveal).
  `showsMask` (`web/js/net.js`) tried to parse each string item of a list as JSON, so a list of
  `"hidden"` never counted as a mask and the row failed as a forged one (`bad`, `why: mask`).
  String items now take the same test as string values of an object: the value `hidden`, `hidden`
  embedded with no hex character next to it, or a fight box id cut to `<prefix>:********:<n>`.
  Such a row is `hidden`, never `ok`. A row marked redacted that shows no mask still fails.
- **The reason of a stopped run.** When the chain run of an entry stops on another row that is
  marked redacted but shows no mask, `verifyEntry` now answers `bad` with `why: chain/mask` and
  `at`, the seq of that row. Before, it answered `why: chain`, which reads as a broken hash link.
  A broken `prev` link, a gap or a hash mismatch still answers `why: chain`.

### Verifier: rules by era

- **Field Luck by era.** The underdog chance of a PvP battle changed to a flat 1% on
  2026-11-25. The verifier replayed every raid with the new value, so an older upset with a roll
  between 1% and the earlier threshold (15% with a 5% floor, 25% with a 10% floor on a revenge
  raid) failed the rule. The earlier rule is kept in `FIELD_LUCK_RULES` (`web/js/fieldluck.js`),
  and `luckRulesAt` (`web/js/ledgerverify.js`) picks the rule from the time of the reveal and the
  time of its drand round: the earlier rule before 2026-11-25 06:25:30 UTC, the flat 1% from
  06:24:00 UTC (the server deploy window of both networks, where either is accepted). A reveal
  dated before the era of its own round matches no rule and fails.
- **Hero Box charges before the snapshot price.** A Hero Box charge records its batch price
  (`refs.price`) since 2026-11-14 07:28:40 UTC (`HERO_BOX_PRICE_REF_FROM`). A charge made before
  that, with no `refs.price`, is now held to the catalog price of its balance era, and so is the
  refund of a same-rarity roll in that batch (half of that price). Only a charge
  whose time and drand round are both before that instant may omit it; a later charge without
  `refs.price` still fails as `price`.
- **Counted raid floor by era.** A raid stamped with a balance version from before the
  2026-11-19 reward factor settled its counted floor at factor 1. The replay now uses that floor
  (`PVP_COUNTED_FLAT_BASE` at the index) for those entries, and the live floor for later ones.

### Rules

- The game server now records, in each `pvpRaid` and `pvpDefense` reveal, the upset threshold
  the roll was compared with (`refs.u`), and in each `pvpRaid` reveal the counted floor
  (`refs.countedMin`, in thousandths of a token). The verifier requires `refs.u` to equal the threshold the
  rule of the entry's era gives for the two recorded fighters, so it never trusts the recorded
  value alone. It checks the counted flag against `refs.countedMin`, which must be above 0 and at
  most the chest share of the rule (`min(chest x PVP.counted, flat)`). Entries without these
  fields verify as before.
- `web/js/pvprules.js`: `resolveRaid` takes an optional `{ rule, countedFlat }` (used by the
  verifier only) and returns `floor`; `countedMin` takes an optional flat floor.
- `web/js/data.js`: `PVP_COUNTED_FLAT_BASE`, the base of `PVP.countedFlat`.

### Game rules already running

The published code is the code the game runs, so this release also carries these rule changes
that are live on the game server.

- **Recruit Grant.** The Recruit Grant rules (`web/js/grant.js`, numbers in `RECRUIT_GRANT` of
  `web/js/data.js`) and their verifier check (`checkGrant` in `web/js/ledgerverify.js`). The
  program is not enabled on mainnet.
- **Hunt engine: Squire farm order (CRY-718).** When the player opts in, the Squire can staff
  mercenaries by their farm rate instead of by rarity; the default order is unchanged. The replay
  reads the recorded `squireFarm` of a leg, and a leg without it replays on the rarity order.
- **Lottery.** The pot is the sum of what each ticket was sold for (`potOf` in
  `web/js/lottery.js`).

Read the `replayed X of N draw entries` line before the verdict. `core-manifest.json` holds the
SHA-256 of every file, the `tree` hash of the whole release and the `rules` commit.
