# v0.1.9

Verifier hardening from external reports and their review, a verifier retry for the deploy window,
and the rule code of the live game since v0.1.8: the Squire on the Market and the shield repair
threshold. Public source for audit, under BUSL-1.1.

## Deployed program

The on-chain program is unchanged from v0.1.4: same program id, same source and the same
verifiable build hashes listed in [v0.1.4](https://github.com/Crypto-of-Thrones/core/blob/v0.1.4/docs/releases/v0.1.4.md).
No file under `programs/` changed.

## Changes

### Verifier: external reports

These issues were reported by independent security researchers. Thank you.

- **One collective record, one reveal.** The collective kinds (`dragonBox`, `lotteryDraw`,
  `bossPrize`, `vigilPrize`) carry no act id, so the one-reveal-per-act bound did not cover them and
  two identical entries for one record each verified. Every copy of such a twin now fails as `bad`
  (`bound`).
- **Acts of another commit.** With a rules reference set, an act whose `rules` label names another
  commit skipped the catalog price check. Such an act, and every reveal that reads it, now ends
  `rules` (the commit to check out), never `ok`.
- **Hunt and away return bounds.** Besides chest + war + `roiCut` = earned, the verifier now holds
  `0 <= roiVault <= roiCut <= earned` (`roiBoundsOk` in `web/js/huntengine.js`), in the hour replay,
  the live hunt check and the `hunt` and `away` payout rules.
- **Hunt hour input.** A replayed hour needs its legs sorted, not overlapping and inside
  `[refs.from, refs.to]` (`legs`), and each leg's realm factors in (0, 1] (`realm`). A recorded
  castle bonus or `farmDays` table must be one the game paid with (`castle`, `farmDays`).
- **Fight Hour days.** A Fight Hour day listed twice in `refs.fight` fails (`fight`).
- **Hero Box shares.** A Hero Box reveal must read exactly the uniforms `[3(box-1), 3box]` of its
  box, and each box opens on the rarity the box before it left.
- **Acts outside the price table.** PvP rerolls, Farm worker summons and lake trips are now priced:
  a free list charges nothing, a paid reroll burns exactly one reroll tier, a worker summon charges
  its catalog cost and a lake trip is free. The offer kind keeps no catalog price, because its price
  is personal to each player.
- **Hold cancel timing.** A cancel that voids a live act must be dated before the round of that act.
  A cancel dated at or after the round fails.
- **Mainnet mode.** With `--mainnet`, a lottery day before the pinned rule fails; the dated
  pre-launch branches (raid without inputs, act without att, joust without win, hunt without engine,
  Hero Box before `refs.price`) and the training floor default are off; and every hunt hour must
  carry the fixed factor and each leg its castle bonus and `farmDays`.
- **Anchors under `--mainnet`.** A run in which every check passed but the anchor step of some entry
  did not run prints `NOT VERIFIED: K of N entries had no anchor read on chain` (`anchorSkip` in
  `--json`) and exits with code 3, never 0. Without `--mainnet` the same run stays `PASS, NOT FINAL`
  with exit code 0. See the README.

### Verifier: deploy window

- After each deploy the public audit route may answer 503 for up to 300 s while the game server
  moves to the new rules. `tools/verify/verify.mjs` now keeps retrying through that window
  (up to 330 s) instead of giving up after about 20 s.

### Rules

- `web/js/data.js`, `web/js/marketrules.js`: a Squire can be listed on the Market between
  `MARKET.squireFloor` (10,000 tokens) and `MARKET.squireTop` (10,000,000 tokens), flat amounts as
  players see them. Selling one needs the season's pass; buying one does not.
- `web/js/data.js`: a shield repair opens only at `POTIONS.repairAtPct` (90%) of its max or below
  (`repairOpen`).
- `web/js/ledgerverify.js`, `web/js/huntengine.js`, `tools/verify/verify.mjs`: the verifier changes
  above.
- `tools/replay-hunt-test.mjs`: tests for the return bounds, the hour input and the recorded tables.

## Verify this release

```sh
git clone https://github.com/Crypto-of-Thrones/core.git && cd core
git checkout v0.1.9
node tools/replay-hunt-test.mjs
node tools/verify/verify.mjs <audit-id> --mainnet --base https://api.cot.gg \
  --rpc https://api.mainnet-beta.solana.com --program Cyz7fwhJomMxGtNtj752YcuoSvKASRaYTzrxhHu31FaC --acct <ACCT>
```

Read the `replayed X of N draw entries` line before the verdict. With `--mainnet` and no `--acct`
the run ends `NOT VERIFIED` with exit code 3, because the anchors are not read on chain.
`core-manifest.json` holds the SHA-256 of every file, the `tree` hash of the whole release and the
`rules` commit.
